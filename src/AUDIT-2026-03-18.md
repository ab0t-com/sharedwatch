## Gaps against spec
### 1. Rename detection is not implemented
Spec asked for rename/move preservation when detectable.
Current behavior is snapshot diff based and will normally represent rename as:
- delete old path
- create new path

Impact:
- acceptable for early v1 behavior
- not fully compliant with requested event semantics

### 2. Active-mode auto-extension is not implemented
Spec says active mode should auto-extend if collaboration continues.
Current behavior:
- TTL can be manually enabled
- expiry works by `EffectiveMode`
- no explicit auto-extension on continued activity

### 3. Consumer loop does not yet honor configured active interval cleanly
Current `Run()` loop uses a fixed 5-second consumer ticker.
That is directionally okay for active mode, but not fully config-driven.

Needed:
- use `cfg.ActiveInterval`
- avoid fixed ticker assumptions

### 4. Passive 10m vs dynamic 5m behavior is implemented partially, not elegantly
Current behavior:
- if recent events happened in last 30m, passive review shifts to 5m
- otherwise 10m

That matches the spec idea, but the runtime loop still polls every 5s and merely decides whether to consume.
This is functionally acceptable but operationally less clean than a real cadence scheduler.

### 5. Reconciler does not yet verify queue/database health beyond snapshot persistence
Spec wanted health verification.
Current reconciler:
- compares snapshots
- emits recovery events
- stores snapshot
- updates runtime state

Missing:
- health checks / failed-event reporting / integrity-oriented checks

### 6. Unread digest semantics are incomplete
Spec suggested `digest list` as unread digests.
Current implementation lists digests generally; it does not maintain a full read/archive lifecycle from CLI.

### 7. Ignore patterns / retention / pruning / config file support are not implemented
Spec called these configurable.
Current code only includes hardcoded defaults in Go.
No YAML config loading yet.
No retention/pruning logic yet.
No ignore pattern filtering yet.

### 8. Observability is minimal, not yet strong
Current observability:
- status command
- basic stdout prints in run loop

Missing from spec intent:
- structured logs
- failed-event visibility in status
- last digest visibility
- stronger queue health reporting

### 9. Database dependency is still externally unresolved
The intended SQLite approach is right, but practical validation is blocked by module fetch trust.
That is an operational gap, not just a cosmetic one.
