## Per-scenario findings

### ✅ Scenario 1 — Single new file
File created, `file.created` event emitted with full attribution and the configured `producer_id`. Baseline correct.

### ✅ Scenario 2 — In-place text edit
Initial `file.created`, then `file.modified` after edit. Size and mtime update propagate as expected.

### ✅ Scenario 3 — Two edits inside coalesce window
Two edits within ~3 s of the first → coalesced into the prior pending event. One visible row, `coalesced_into` populated on the swallowed event. Behaves per the 5 s default window.

### ✅ Scenario 4 — Two edits straddling the coalesce window
First edit + 6 s wait + second edit → two distinct events. Confirms the off-by-one of the window boundary.

### ✅ Scenario 5 — Rename within root
`mv orig.md renamed.md` → one `file.renamed` event with `old_path=orig.md`, `rel_path=renamed.md`. Heuristic (same size + mtime) fires correctly.

### ✅ Scenario 6 — Move directory subtree
`auth/` → `services/auth/`. Detected as 3 renames (one per file). Mtime preserved by `mv` on this Linux/ext4 host, so the heuristic catches all three. **Result: 3 file.renamed events**, no phantom delete+create pairs.

### ✅ Scenario 7 — Editor swap-file pattern (vim atomic write)
`.swp` file correctly ignored by the default pattern; the `mv .swp → target` is detected as a `file.modified` on the target. No spurious delete+create.

### ✅ Scenario 8 — Bulk find-and-replace via sed
10 files modified by sed in tight succession → 10 distinct `file.modified` events. No cross-path coalesce.

### ✅ Scenario 9 — Two-agent handoff (THE canonical multi-agent flow)
End-to-end verified:
1. `claude-spec` heartbeats, writes `specs/widget.md` with `--addressee claude-code --tag spec`.
2. `claude-code` queries `events list --payload-key addressee --payload-value claude-code` → finds the spec event, captures its id as `SPEC_EVT`.
3. `claude-code` writes `code/widget.go` with `--ref $SPEC_EVT`.
4. `claude-spec` queries `events list --payload-key ref_event_id --payload-value $SPEC_EVT` → finds the response event with `actor=claude-code, task=implement-widget`.

The loop closes. This is the load-bearing scenario proving the multi-agent coordination story works in practice, not just in design docs.

### ✅ Scenario 10 — Concurrent edits in active mode
Active mode (`--ttl 2m`) + two background writers (10 events each) + 4 s wait. Daemon picked up the changes, consumed them into two digests within the active 5 s cadence (50 events in the first digest, 2 in the second — the first digest captured leftover scenario state too).
**Implementation note:** initial dogfood-runner script had a bug — `wait` (no args) blocked on the daemon as well as the writers. Fixed by `wait $A_PID $B_PID` to wait only on the writer PIDs. Documented in the runner; doesn't affect sharedwatch behavior.

### ✅ Scenario 11 — Restart safety mid-batch
20 pending events planted, daemon started, killed with SIGKILL after 1 s. Post-crash status: `pending: 42` (extra count from prior-scenario leftovers in the journal). `events recover-stuck --older-than 0s` reported "no stuck processing events" (correctly — the kill happened before the consumer claimed anything, so events stayed in `pending` rather than getting stuck in `processing`). Subsequent `consume` drained pending to 0.
**Implementation note:** the SIGKILL leaves the file lock orphaned; runner cleans `<data_dir>/sharedwatch.lock` between scenarios. Worth surfacing as a future enhancement: have `sharedwatch run` check for a stale lock (PID not alive) at startup and reclaim instead of refusing to start.

### ✅ Scenario 12 — Large file above HashMaxSize
2 MB file with `--hash on` → event recorded with `file_size=2097152` and `content_hash=NULL` (correctly above the 1 MB default `HashMaxSize` cap).

### ⚠️ Scenario 13 — Ignored patterns (BUG FOUND + FIXED)
Setup: `.git/objects/abc`, `.DS_Store`, `scratch.tmp`, `file.swp`, `real.md`. Expected: only `real.md` event.

**Bug:** `.git/objects/abc` produced an event. Investigation showed that `catalog.Ignored()` was matching only on the basename, full rel_path, and exact equality — never on intermediate path segments. The default `.git` pattern matched only a file literally named `.git`, not files inside a `.git/` directory.

**Fix:** extended `Ignored()` to also check each path segment. `.git/objects/abc` now matches because one of its segments is `.git`. New test `TestIgnoredMatchesDirectorySegment` covers 10 representative cases including `.git/HEAD`, `auth/.git/config`, `node_modules/foo/index.js`, plus negative cases like `.gitignore` (NOT ignored — `.gitignore != .git`) and `docs/git-tutorial.md` (NOT ignored — no segment equals `.git`).

This is exactly what dogfood was designed to find — a documented behavior that didn't match the implementation. Caught before merge.

### ✅ Scenario 14 — Cold start with 50 pre-existing files
Fresh DB + 50 pre-existing files → first reconcile produced 50 events. Each `file.created` from `source=reconciler` per the cold-start emission contract.

### ✅ Scenario 15 — Reconcile catches missed event
File created and reconciled (event_count=1), then "stealth edit" applied while no watcher running. Subsequent reconcile reported `recovery_events=1` — confirming reconcile detected the drift. The new modification coalesced into the existing pending `file.created` (since create→modify inside the window stays as `file.created`), which is the documented design.

The intent of the scenario (prove reconcile sees missed changes) is satisfied by the `recovery_events=1` line. Coalesce behavior is correct.

### ✅ Scenario 16 — Burst of 50 events in active mode
Active mode, 50 files created at ~5/sec, daemon running. Captured: pending=0, failed=0, **6 digests produced** (each digest a consume cycle), `COUNT(*) = 50` events for `burst_%`. The 5 s active-mode cadence consumed events as they arrived; no backlog.

### ✅ Scenario 17 — Cross-actor churn on same file (SW-AGENT-11 regression check)
Two synthetic emits on `auth/login.go` with different actors, within the 5 s coalesce window. Result: 2 distinct events with `actors: ['claude-A', 'claude-B']` preserved. **Confirms the SW-AGENT-11 fix lands correctly** — the previously-silent attribution loss is gone.

### ✅ Scenario 18 — Symlink to outside the watched root
Symlink `outside-link → $DOG/external_target.txt` captured as an entry with `file_size=44` (the length of the target path string — Go's `filepath.WalkDir` does NOT follow symlinks by default, so the entry IS recorded but reflects the symlink metadata, not the target). Modifying the target produced 0 new events on subsequent reconcile (`recovery_events=0`) — confirming symlinks are NOT followed. Behavior is deterministic and matches the design note ("symlinks: deferred to a separate hardening pass").

## What the dogfood pass tells us about v0.8.0

1. **Multi-agent canonical handoff (S9) works end-to-end.** The whole reason this branch exists is solved in practice, not just in docs.
2. **Cross-actor coalesce isolation (S17) confirms SW-AGENT-11 lands cleanly.** The silent-attribution-loss bug is closed.
3. **All v0.7 behaviors preserved.** S1–S8 (basic operations, rename, sed, coalesce) behave identically to pre-v0.8 expectations.
4. **The dogfood plan caught a real bug (S13)** — exactly what it was designed to do. Fixed before merge with a focused regression test.
5. **Reconcile-as-safety-net (S15) works.** Drift is detected; merge semantics are correct.
6. **Active mode + restart safety (S10, S11, S16) hold up** under concurrent writes + crash + recovery.

## Recommended follow-ups (NOT blocking v0.8.0)

- **Stale-lock detection in `sharedwatch run`** — automatically reclaim a lock whose PID isn't alive. Avoids manual `rm` after a crash.
- **Make the dogfood runner a `make dogfood` target** — fold the script into the Makefile and capture the artefact tree as the canonical regression baseline. Re-run after every major release.
- **Tighter `events list --since` scoping in the runner** — start each scenario with a clean timestamp boundary so per-scenario JSONL artefacts don't bleed prior teardown events.
- **Investigate whether `events list --until` should auto-default to "now"** so trimming windows cleanly is easier.
