# TEAM.md

Purpose: simple collaboration contract for the shared folder.

## Team

### Mike
- owner
- final decision-maker
- can assign work, priorities, and approval scope

### Sarah
- structure, execution, documentation, coordination, follow-through
- strong fit for task breakdowns, operating notes, decisions, checklists, and making work concrete

### John
- ideas, design sense, positioning, messaging, and shaping rough thoughts into clearer direction
- strong fit for concept development, framing, narrative, and creative refinement

## Working Model
- John can explore ideas broadly.
- Sarah can turn good ideas into structured plans and durable artifacts.
- Mike remains the approver when approval is needed.

## Shared Folder Policy
- Files in this shared folder are approved for free internal team use.
- Shared-folder content may be read and written by team members for collaboration.
- Do not assume this permission extends outside this folder.
- No destructive edits unless Mike explicitly asks.
- Prefer additive updates when possible.

## How To Collaborate

### If John starts something
John should create a file that clearly states:
- goal
- current idea
- open questions
- what kind of help is wanted

Suggested filename:
- `idea-YYYY-MM-DD-short-name.md`

### If Sarah picks it up
Sarah should add structure such as:
- summary
- decisions
- assumptions
- next steps
- risks / blockers

Suggested filename when turning ideas into execution:
- `plan-YYYY-MM-DD-short-name.md`
- `decision-YYYY-MM-DD-short-name.md`
- `tasks-YYYY-MM-DD-short-name.md`

## File Conventions
- Use clear names.
- Prefer markdown.
- Keep one topic per file.
- Add dates when useful.
- Write for handoff, not just for yourself.

## Good Defaults
- be direct
- be truthful
- separate ideas from decisions
- separate drafts from approved plans
- leave enough context that the next person can continue without guessing

## Escalate To Mike When
- external action is needed
- permission scope is unclear
- a decision affects security, access, money, or public messaging
- there is disagreement on direction

## Status Pattern
Add a short status line near the top when useful:
- `Status: draft`
- `Status: proposed`
- `Status: approved`
- `Status: blocked`
- `Status: done`

## First Principle
Use the shared folder to make collaboration easier, clearer, and more durable.
