# sharedwatch — full-CLI usability audit

**Date:** 2026-05-25 05:40:51 UTC
**Binary audited:** dev build at `src/.bin/sharedwatch` on `feature/on-digest-hooks` (= SW-AGENT-29 + SW-AGENT-30 + everything prior)
**Method:** 6 parallel Explore sub-agents (very-thorough depth) each owning a slice of the CLI surface, then synthesised + reconciled by the lead.
**Coverage:** every documented subcommand + flag + env var + config key + new SW-AGENT-29/30 event types. ~250 distinct command invocations across all agents.

---

## 0. Executive summary

**The CLI is in good shape.** Of 44 raw findings across 6 audit slices, **2 are real high-severity** issues worth fixing soon, **~18 are real medium-severity** friction items (mostly cross-cutting consistency + documentation gaps), and the rest are polish.

**The two real high-severity items both come from the help/discoverability surface:**

1. Duplicate `events retry` / `events recover-stuck` entries in the COMMANDS help block (cosmetic but misleading — operators see contradictory flag specs).
2. `lease grant --format` is an undocumented deprecated flag that is **read-but-never-used**: assigned to a local `asJSON` var, immediately discarded via `_ = *asJSON`. Dead code that pollutes the help surface.

**Three of Agent 3's "high-severity" findings were re-classified after reconciliation:**

- `events list --json` → JSONL (not JSON object): **intentional** per SW-AGENT-25 design (streaming commands use JSONL).
- `intent list --json` / `lease list --json` returning zero bytes on empty: **intentional** per SW-AGENT-23 (matches `events list --format jsonl` convention).
- `sql / events stats / digest show ignore --format`: **wrong** — I verified all three respect `--format` correctly. Agent likely hit the known "flag after positional arg" Go-stdlib gotcha.

**Net:** every critical contract (resolution chain, cursor idempotency, lease/intent/actor lifecycle, hook subprocess isolation, emit-profile tier gating) is verified working. The remaining work is consistency polish + documentation completeness.

## 2. Verified-real high-severity findings

### H1. Duplicate `events retry` / `events recover-stuck` lines in COMMANDS help (A1)

**Where:** `src/cmd/sharedwatch/main.go` lines ~1714 and ~1729 (the `usage(root)` printer).
**What:** the COMMANDS section lists each twice with different flag specs:
```
events retry [--max-retries N]
events retry [--dry-run]
events recover-stuck [--older-than 5m]
events recover-stuck [--dry-run]
```
An operator reading help sees contradictory flag advertisements.
**Fix:** consolidate to single lines per command, e.g. `events retry [--max-retries N] [--dry-run]`.

### H2. `lease grant --format` is dead code (A1)

**Where:** `src/cmd/sharedwatch/main.go` lines ~1268 + ~1324.
**What:** the flag is declared as `asJSON := fs.Bool("format", false, "deprecated; emits JSON")`, then immediately discarded via `_ = *asJSON`. The handler always outputs JSON anyway. The flag appears in `lease grant --help` but does nothing.
**Fix:** delete the declaration AND the discard line. JSON-always is the intended behaviour; the deprecated alias has no transitional value because (a) it was always a no-op, (b) no one's pipeline depends on it.

## 4. Medium-severity findings (real friction; worth addressing in a polish ticket)

Grouped by theme. Each entry: `[id]` finding — *where* — fix recommendation.

### 4a. Output-contract consistency

- **[M-cross-1]** Text vs JSON field-naming split across intent/lease/digest list. Text says `actor=foo path=bar renewals=3`; JSON says `actor_id`, `path_glob`, `renewal_count`. Same data, two vocabularies. — fix: align both forms; recommend JSON names ("actor_id", etc.) since they're already documented and pipe-friendly.
- **[M-cross-2]** `--json` vs `--format` flag inconsistency across subcommands. Some accept both (events list, sql, schema, overview, events stats); some only `--json` (status, roots, config show, intent list, lease list); one only `--format` (digest list). — fix: either add `--json` to digest list, OR document the split clearly in each `--help`.
- **[M-cross-3]** `events list --fields id,type,rel_path --format json` returns rows with keys in **alphabetical** order, not requested order. Text and JSONL preserve order. — fix: use ordered Marshal for the JSON path, or document the alphabetical reorder.
- **[M-cross-4]** Empty result rendering varies: JSONL → no output; CSV → headers only; text → headers only; JSON → `{"columns":..., "rows":[]}`. — fix: document the per-format empty-case in the output-contract reference.

### 4b. Documentation completeness

- **[M-doc-1]** README env-var table missing all 4 SW-AGENT-29/30 vars (`SHAREDWATCH_ON_DIGEST`, `_ON_DIGEST_TIMEOUT`, `_EMIT_PROFILE`, `_EMIT_OVERRIDE`). They're in `knownEnvVars` and `config show` lists them, but README is incomplete.
- **[M-doc-2]** `Skills/sharedwatch-client/references/config-file.md` still lists only the SW-AGENT-18 keys; missing the 4 SW-AGENT-29/30 YAML keys + 10+ agent-default keys that already work.
- **[M-doc-3]** `docs/guides/on-digest-hooks.md` §2 example shows `sharedwatch run --on-digest '…'` — wrong flag position; Go stdlib silently drops it. Should be `sharedwatch --on-digest '…' run`.
- **[M-doc-4]** Path-glob case sensitivity unstated. `--path-glob FILE*` fails to match `file.md`. Real behaviour (case-sensitive on Unix per `filepath.Match`); just needs a doc note.
- **[M-doc-5]** The default `emit_thresholds` values (`events_failed=50`, `events_stuck=10`, `reconcile_drift=25`) are hardcoded in `config.go:Default()`; no user-facing reference lists them outside `config show --json`.

### 4c. Subcommand-specific friction

- **[M-sub-1]** `--root` filter accepts label that doesn't exist in configured roots — silently returns 0 events. — fix: suggest "available labels" in error or as a soft warning.
- **[M-sub-2]** `--config /nonexistent/path.yaml` silently falls through to other config search paths. The search trail (`config show --json | jq .config_files_searched`) reveals the truth, but the user gets no error. — fix: when `--config` is explicit, ERROR if not present (existing code has a TODO matching this).
- **[M-sub-3]** Unknown class in `emit_overrides` silently ignored (forward-compat — good intent), but typo `digests=true` instead of `digest=true` has no operator feedback loop. — fix: log a warning to stderr at config-resolution time for unknown class names.
- **[M-sub-4]** `Config.StorageType` field exists, defaults to `"sqlite"`, but no YAML key parses it + no env + no flag + nothing reads it. Dead code with comment. — fix: either delete the field or wire it up.
- **[M-sub-5]** `lease.violated` payload has `"violator_actor": ""` when the source event lacks an actor. — fix: omit the field with `omitempty` (clearer "no actor attribution available") or fall back to `producer_id`.

### 4d. Discoverability

- **[M-disc-1]** `<subcommand> --help` (e.g. `events list --help`) returns global usage, not per-subcommand help. This is intentional (per SW-AGENT-26 — avoids creating a DB on help probe) but non-obvious. — fix: add a one-liner to global help: "for per-subcommand flag details, run `sharedwatch help` (or read the docs at …)".
- **[M-disc-2]** Flag reordering magic (`sharedwatch status --json` ≡ `sharedwatch --json status`) is undocumented. — fix: note in global help.
- **[M-disc-3]** `SHAREDWATCH_ROOT` env var name looks like it should DEFINE roots but actually defaults the `--root` FILTER on read commands. Misleading. — fix: rename env var (breaking — defer) OR document loudly.

## 8. Cross-cutting: what works really well

The audit found **zero data-loss, zero deadlock, zero broken-cursor regression**. Highlights from each slice:

- **Resolution chain** (A2): all 17 fields tested cleanly resolve flag > env > config > default. Unknown profile warns + falls back rather than bricking. Map fields (overrides, thresholds) correctly merge across layers.
- **Coord lifecycle** (A4): all 9 multi-actor workflows pass — intent race, exclusive lease conflict, violation detection (both watcher AND reconciler paths), expiry-then-prune ordering, actor heartbeat lifecycle, lease renewal TTL capping, status --actors stale marking.
- **Events / cursor / SQL** (A5): 54 scenarios across filter combinations, cursor idempotency, format outputs, retry/recover-stuck dry-runs. Cursor advancement is monotonic and idempotent.
- **SW-AGENT-29/30** (A6): tier matrix verified (minimal → standard → verbose → all, strict superset progression); hook subprocess isolation tight (timeout / exit code / sidecar files all match documented contracts); backwards compat airtight (minimal tier = exact v0.0.x event surface).
- **Threshold gating** (A4, A6): `events.failed_threshold` and `events.stuck_detected` correctly fire when count exceeds threshold AND stay quiet below. Per-cycle emission (not rising-edge) per design.

## 10. Verdict + recommendation

The CLI is **production-quality for v0.1.1 release**. The 2 real high-severity items are 10-minute fixes; the 18 medium items are a clean polish sprint worth ~half a day if bundled.

**Suggested next steps in priority order:**

1. **Quick wins (this sprint)**: Top-5 from §1 — fix the 2 high-severity + 3 documentation polishing items. Total ~90 min.
2. **Field-naming alignment** (separate small ticket): close the long-running text-vs-JSON split per §6.
3. **Documentation completeness** (separate small ticket): README env table + config-file reference + path-glob case-sensitivity note + emit_thresholds defaults note.
4. **`config.StorageType` cleanup** (drive-by): either wire it up or delete the field.
5. **Rising-edge for failure-threshold events** (separate ticket — already deferred per SW-AGENT-30 design): the per-cycle behaviour is acceptable for v0.1.1 but won't scale to alert-noise-sensitive ops use cases.

Nothing in this audit suggests blocking the SW-AGENT-30 work that's already merged on the feature branch. The branch is ready for whatever review/merge gating you want to apply.
