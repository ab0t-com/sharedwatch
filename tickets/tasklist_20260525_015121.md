## 0. What this ticket delivers

Per the principle reframe: **emit liberally, hooks stay narrow.** This ticket fills out the event surface (~20 new event types) and adds the tier-profile config that lets clients choose what they consume.

Existing features are **unchanged and extended**, not replaced:
- File events still emit unconditionally at all tiers (including `minimal`).
- `--on-digest` hook surface from SW-AGENT-29 is untouched. New event types compose with it.
- All cursor / filter / format semantics remain unchanged. New types use the existing surface for free.
- Retention pipeline unchanged. New types prune at `retention_days`.

What's NEW:
- ~20 new event types covering daemon lifecycle, mode transitions, reconcile observability, retention evidence, failure thresholds, coord events (lease/intent), actor lifecycle, and optionally actor heartbeats / mode TTL extensions.
- 5 new event sources: `daemon`, `mode`, `coord`, `actor`, `retention`. (Existing `watcher`, `reconciler`, `test`, `hook` untouched.)
- A `internal/events/profile.go` package with a `ShouldEmit(eventType, profile, overrides) bool` central authority. Every emit site routes through it.
- Tier-profile config (`emit_profile` + `emit_overrides` + `emit_thresholds`) with smart defaults — see §2.
- Documentation: a new `docs/guides/event-broker.md` operator-facing guide written from the consumer catalog in the discussion doc.

## 1. Decisions baked into this tasklist

Per `docs/design/event-broker-consumer-contracts-20260525.md` §6, resolved best-practice with no over-engineering:

| OQ | Decision | Reasoning |
|---|---|---|
| OQ-1: explicit `digest.created` event? | **YES** | Symmetry — every other operation emits an event. Cost: one `InsertEvent` call. |
| OQ-2: separate `emit_thresholds` map? | **YES, with only 3 thresholds** | Keeps toggles separate from tuning. Three thresholds (`events_failed`, `events_stuck`, `reconcile_drift`); don't generalise to "configurable for everything." |
| OQ-3: per-class vs per-event override granularity? | **per-class for v1** | Classes are small enough; revisit only if users actually ask for per-type. |
| OQ-4: per-root emit profiles? | **uniform for v1** | Per-root multiplies config complexity for zero demonstrated demand. |

Additional decisions:

| Q | Decision | Reasoning |
|---|---|---|
| Default tier | `standard` | Covers ~95% of integration cases per the consumer catalog. |
| Rising-edge for threshold events | **YES** | `events.failed_threshold` fires when count crosses N upward; not every reconcile cycle while count stays above. Mitigates paging spam. |
| New sources or reuse existing? | **New per-class** | `daemon`, `mode`, `coord`, `actor`, `retention` — each its own source. Enables `--source daemon` queries. |
| Watch-root propagation | **Daemon-wide events: empty `watch_root`. Per-root events: stamped.** | Convention; documented in broker guide. |
| Backwards compat for new types at `minimal` tier | **All NEW types are above `minimal`** | A user on `minimal` gets exactly v0.0.x event surface — no surprise emissions. |

## 2. Configuration shape (final)

```yaml
emit_profile: standard            # default; minimal | standard | verbose | all
emit_overrides:                   # optional
  actor_heartbeats: true          # opt INTO a verbose-tier class
  reconcile_per_cycle: false      # opt OUT of a standard-tier class
emit_thresholds:                  # optional, only 3 knobs
  events_failed: 50               # rising-edge: fire when failed count crosses 50
  events_stuck: 10                # rising-edge: fire when stuck count crosses 10
  reconcile_drift: 25             # fire when recovered count > 25 in one pass
```

Env vars (resolution chain: flag > env > config > default):
- `SHAREDWATCH_EMIT_PROFILE=standard`
- `SHAREDWATCH_EMIT_OVERRIDE=actor_heartbeats=true,reconcile_per_cycle=false` (comma-separated key=bool list)

Root flags:
- `--emit-profile <tier>`
- `--emit-override <class>=<bool>` (repeatable)
- (Thresholds are operator-only config-file knobs; no flag.)

`config show` extensions:
- text mode: rows for `emit_profile`, `emit_overrides`, `emit_thresholds`
- JSON mode: same keys in the `effective` envelope, plus a **derived** `emit_effective_classes` showing which classes actually emit after profile + overrides resolve

## 3. Event types being added

Total: **20 new event types** + 5 new sources. Names below are stable contracts — never rename once shipped.

### standard tier (low volume, high integration value)

| Type | Source | When | Payload (key fields) |
|---|---|---|---|
| `digest.created` | `daemon` | After every digest INSERT commits | `digest_id`, `event_count`, `window_start/end`, `mode`, `watch_root` |
| `daemon.started` | `daemon` | After lock acquired, before main loop | `version`, `pid`, `mode`, `watch_paths[]`, `started_at` |
| `daemon.stopping` | `daemon` | Before WaitForHooks / lock release | `reason: "sigterm"\|"sigint"\|"explicit-stop"`, `pid`, `uptime_ms` |
| `daemon.crashed` | `daemon` | On next startup after stale-lock detection | `prior_pid`, `prior_lock_age_ms`, `recovered_at` |
| `mode.changed` | `mode` | Active↔passive transitions | `from`, `to`, `trigger: "explicit"\|"ttl-expired"\|"event-burst"`, `ttl_secs?` |
| `retention.ran` | `retention` | Per reconcile cycle (low volume) | `events_pruned`, `digests_pruned`, `snapshots_pruned`, `actors_pruned`, `intents_pruned`, `leases_pruned`, `duration_ms`, `retention_days` |
| `events.failed_threshold` | `daemon` | Rising-edge when failed count crosses `emit_thresholds.events_failed` | `count`, `threshold`, `oldest_failed_id` |
| `events.stuck_detected` | `daemon` | Rising-edge when stuck count crosses `emit_thresholds.events_stuck` | `count`, `threshold`, `oldest_age_secs` |
| `events.retried_batch` | `daemon` | After `events retry` requeues N | `count`, `after_failures` |
| `lease.granted` | `coord` | After `lease grant` succeeds | `lease_id`, `actor`, `path_glob`, `ttl_secs`, `expires_at`, `exclusive` |
| `lease.released` | `coord` | After `lease release` | `lease_id`, `actor` |
| `lease.renewed` | `coord` | After `lease renew` | `lease_id`, `actor`, `new_expires_at`, `renewal_count` |
| `lease.expired` | `coord` | Per reconcile cycle, for each pruned expired lease | `lease_id`, `actor` |
| `lease.violated` | `watcher` | When watcher detects foreign write inside an active lease | `violator_actor`, `lease_actor`, `lease_id`, `path_glob`, `observed_event_id` |
| `intent.declared` | `coord` | After `intent declare` | `intent_id`, `actor`, `path_glob`, `task`, `intent_text`, `ttl_secs`, `expires_at` |
| `intent.revoked` | `coord` | After `intent revoke` | `intent_id`, `actor`, `reason: "explicit"` |
| `intent.expired` | `coord` | Per reconcile cycle, for each pruned expired intent | `intent_id`, `actor`, `reason: "expired"` |
| `actor.registered` | `actor` | First heartbeat for a new actor_id | `actor`, `kind`, `focus`, `first_seen_at` |
| `actor.removed` | `actor` | Per reconcile cycle, when prune past 2× ActorTTL | `actor`, `last_heartbeat`, `removed_after_secs` |

### verbose tier (medium volume; opt-in)

| Type | Source | When | Notes |
|---|---|---|---|
| `reconcile.ran` | `reconciler` | Per reconcile cycle (default 30 min) | `duration_ms`, `events_recovered`, `snapshots_taken` |
| `reconcile.drift_detected` | `reconciler` | When per-cycle recovery count > `emit_thresholds.reconcile_drift` | `watch_root`, `recovered`, `threshold` |
| `mode.ttl_extended` | `mode` | Every active-mode emit extends TTL | `expires_at`, `extension_secs` |
| `actor.went_stale` | `actor` | Per reconcile cycle, when actor past 1× ActorTTL but < 2× | `actor`, `last_heartbeat`, `stale_since_secs` |
| `snapshot.taken` | `reconciler` | Per reconcile pass per root | `watch_root`, `file_count`, `duration_ms` |

### all tier (high volume; full audit only)

| Type | Source | When | Notes |
|---|---|---|---|
| `actor.heartbeat_received` | `actor` | Every heartbeat write | `actor`, `kind`, `focus` |

(snapshot.failed, db.error are listed in the discussion doc but deferred to a later ticket — they require error-path instrumentation that's larger scope.)

## 4. Implementation tasklist

Each item is a discrete commit. Order is dependency-driven — each checkpoint compiles and tests pass.

### Phase 1 — config plumbing (no behaviour change)

- [ ] **1.1** `config.Config`: add `EmitProfile string` (default `"standard"`), `EmitOverrides map[string]bool` (default empty), `EmitThresholds map[string]int` (default `{events_failed:50, events_stuck:10, reconcile_drift:25}`).
- [ ] **1.2** YAML loader (`internal/config/file.go`): parse `emit_profile`, `emit_overrides` (single-line `k=v,k=v` inline map), `emit_thresholds` (same inline form). Hand-rolled YAML scanner; mirror existing inline-map handling.
- [ ] **1.3** Env vars (`cmd/sharedwatch/env_glue.go`): `SHAREDWATCH_EMIT_PROFILE` + `SHAREDWATCH_EMIT_OVERRIDE`. Add to `knownEnvVars`.
- [ ] **1.4** Root flags (`cmd/sharedwatch/main.go`): `--emit-profile <str>`, `--emit-override <k=v>` (repeatable). Resolution: flag > env > config > default.
- [ ] **1.5** Extend `config_show.go` DTO + text rows + add a **derived** `emit_effective_classes` map showing which classes will actually emit. Operator verification surface.
- [ ] **1.6** Empirical: `config show --json` shows the right values for default / env / flag / file precedence chain.

### Phase 2 — emit-decision authority

- [ ] **2.1** New package `internal/events/profile.go`:
  - `Class string` type (constants: `"file"`, `"reconciler"`, `"hook"`, `"digest"`, `"lifecycle"`, `"mode_change"`, `"mode_ttl"`, `"retention"`, `"failure_threshold"`, `"coord"`, `"actor_lifecycle"`, `"actor_heartbeat"`, `"snapshot"`, `"reconcile_per_cycle"`, `"reconcile_threshold"`).
  - `TierClasses(profile string) map[Class]bool` — returns the enabled classes for a profile (minimal/standard/verbose/all).
  - `TypeClass(t events.Type) Class` — maps each event type to its class.
  - `ShouldEmit(t events.Type, profile string, overrides map[string]bool) bool` — the central authority every emit site calls.
- [ ] **2.2** Unit tests covering: profile=minimal hides everything but file/reconciler/hook; profile=standard includes default standard set; overrides opt-in raises class above tier; overrides opt-out demotes it; unknown class name in overrides is ignored (don't error — forward-compat).
- [ ] **2.3** Empty event types / empty profile = backwards-compat default (don't accidentally suppress file events).

### Phase 3 — event type + source constants

- [ ] **3.1** `internal/events/events.go`: add 20 new `events.Type` constants (per §3 above) + 5 new `Source` constants. Each constant grouped with comments explaining when emitted.
- [ ] **3.2** No new tests yet — these are dead constants until Phase 4 wires emit sites.

### Phase 4 — emit sites (the bulk of the work)

Each emit site wraps in `if profile.ShouldEmit(t, cfg.EmitProfile, cfg.EmitOverrides) { _ = store.InsertEvent(ctx, ...) }`. Failures are non-fatal (log + continue) so emit issues never block real work.

- [ ] **4.1** `digest.created` — `consumer.ConsumePending` after `InsertDigest` succeeds. Threaded via the existing app.App `FireHookAsync` pattern OR a new `EmitDigestEvent` helper.
- [ ] **4.2** Daemon lifecycle — `app.App.Run` and `cmd/sharedwatch/main.go` shutdown path:
  - `daemon.started`: after lock acquired, before main loop.
  - `daemon.stopping`: in the deferred close path (before `WaitForHooks`).
  - `daemon.crashed`: in `acquireRunLock` when stale-lock detection fires.
- [ ] **4.3** Mode transitions — `app.App.SetActive` / `SetPassive`. Detect transition by comparing prior runtime state vs. new state. Emit `mode.changed` on actual transitions; emit `mode.ttl_extended` (verbose) on every TTL extension.
- [ ] **4.4** Reconcile observability — `reconcile.postPasses`:
  - `reconcile.ran` (verbose): always, with stats.
  - `reconcile.drift_detected` (standard): when `events_recovered > threshold`.
  - `reconcile.recovered_threshold` (standard): when count crosses `emit_thresholds.reconcile_drift` upward.
- [ ] **4.5** Retention pass — `reconcile.postPasses` after `PruneArchivedDigests` etc.: emit `retention.ran` with counts.
- [ ] **4.6** Failure thresholds — `reconcile.postPasses`:
  - `events.failed_threshold`: count `failed` rows; rising-edge against `emit_thresholds.events_failed` (track prior count in runtime state).
  - `events.stuck_detected`: count `processing` rows older than 5 min; rising-edge against `emit_thresholds.events_stuck`.
  - `events.retried_batch`: in `events retry` handler after requeue succeeds.
- [ ] **4.7** Coord — `lease grant/release/renew` handlers in `main.go`; `lease.expired` in `reconcile.postPasses` after `PruneExpiredLeases`; `intent declare/revoke` handlers; `intent.expired` after `PruneExpiredIntents`.
- [ ] **4.8** Lease violation — in `internal/watcher/service.go` where lease checks already happen for `slog.Warn`. Wrap the warn call to ALSO emit `lease.violated`.
- [ ] **4.9** Actor registry — `actor heartbeat` handler emits `actor.registered` (first time only — needs a check against existing rows) and `actor.heartbeat_received` (verbose); `reconcile.postPasses` emits `actor.went_stale` (verbose) and `actor.removed` (standard).
- [ ] **4.10** Snapshot events — in reconcile per-root scan: `snapshot.taken` (verbose) after successful snapshot.

- [ ] `sharedwatch run --emit-profile all --emit-override actor_heartbeats=false` shows that overrides demote a class below its tier.

## 7. Risks + mitigations

| Risk | Mitigation |
|---|---|
| Verbose-tier emission floods a test environment and breaks unrelated tests | Default tier in tests is `minimal` (or whatever the existing tests assume); verbose is opt-in per-test. |
| New event types collide with future user expectations | Type names follow the existing `<class>.<verb>` convention. Reserve `*` prefixes (no `*.timeout` namespace conflicts). |
| Rising-edge state for thresholds gets lost on daemon restart | Store the prior count in `runtime` row (same place `LastReconcileRun` lives). Restart sees the prior threshold-state; doesn't re-fire on resume. |
| Coord events fire from multiple call sites (CLI grant + reconcile expiry) and double-count | Each emit site is one specific lifecycle step; never both fire for the same `lease_id`. Acceptance tests verify. |
| Threshold defaults are too sensitive / too lax for real workloads | Defaults are tunable via `emit_thresholds` map. Document expected ranges in the broker guide. |
| `digest.created` event arrives BEFORE the `hook.completed` event for the same digest (consumers seeing them in unexpected order) | Document the ordering: `digest.created` ALWAYS lands first (sync from consumer); `hook.completed` follows async after the hook subprocess finishes. |
