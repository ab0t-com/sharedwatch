**Deferred from F:**
- [ ] **F3** Cursor stability against reconcile-inserted late events — semi-theoretical (in practice reconcile timestamps == snapshot time == "now", so events arrive ordered). The cursor design IS correct against the hypothetical case (filter is `created_at > X OR (created_at = X AND id > Y)`), but the dogfood scenario to trigger it requires backdating an event timestamp, which the public CLI doesn't allow. Verified via unit reasoning, not end-to-end. Filed as a follow-up test.

**Bugs caught and fixed during dogfooding (post-implementation, pre-release)**
- **B2-bug:** named-cursor first call (empty cursor) was iterating DESC then saving the cursor at the oldest-shown row. Second call then re-emitted events that were *newer* than that. Fix: when `--cursor-name` or `--since-cursor` is set, force iteration ASC regardless of `--order`. Behavior now matches the ticket §3.B spec ("Always ASC regardless of `--order` for display").
- **C4-bug:** `sharedwatch sql - --format jsonl` failed because Go's flag parser stops at the first positional, treating `--format jsonl` as more SQL. Fix: pre-extract `-` from args before flag-parse, so flag order vs `-` doesn't matter.

**Acceptance evidence**
- A1: `events list --limit 5` → 5 rows in default text format with header.
- A2: `events list --type file.modified --path-glob 'auth/**' --format json` → 3 rows under `rows`, `format_version: 1`, no cursor (no cursor mode active).
- A3: `events list --limit 0 --order asc --format jsonl | head -10` → 5 row lines + cursor sentinel `{"format_version":1,"next_cursor":"..."}` on the last line.
- A4: `events list --fields id,type,rel_path,created_at --format csv` → 5 rows + only 4 columns. CSV header included.
- B1: stateless cursor round-trip — extracted cursor from JSONL output via `python3 -c json.loads`, fed back via `--since-cursor`, got the remaining 3 events + a new cursor.
- B2: three back-to-back calls with `--cursor-name agent-x --limit 2` returned `(e3859, e7c58)` → `(ee0e9, ea599)` → `(e3f08)`. Zero overlap.
- B3: `--no-advance` peek works; subsequent reads of the same cursor still see the same first event.
- B4: `events cursor encode --created-at <ts> --id <id>` → token; `events cursor decode <tok>` → original `created_at` + `id`.
- C1: `sql "SELECT COUNT(*) AS n FROM events"` → `n\n5`.
- C2: `sql "DELETE FROM events"` → `error: non-SELECT statements require --write: query begins with "DELETE"`, exit 2, with hint line on stderr.
- C3: `sql --write "UPDATE events SET retry_count = 99 WHERE id = ..."` → applied; follow-up SELECT confirms.
- C4: both `sql - --format jsonl` and `sql --format jsonl -` accept stdin and emit JSONL.
- E1: `schema` prints DDL for `cursors`, `digests`, `events`, `runtime_state`, `snapshots` (alphabetical). `schema events --format json` returns structured column metadata.
