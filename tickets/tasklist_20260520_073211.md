New `TestCursorDoesNotSkipBackdatedEvent` directly inserts an event with a timestamp earlier than the cursor, confirms the cursor surfaces only events *after* itself (the documented contract), and confirms a fresh from-start read still sees the backdated event. So: cursor advance never *loses* late events, just doesn't surface them to a consumer that's already past them. (`internal/db/cursor_test.go`)

- [x] **H1–H5** Content-hash population. `cfg.HashEnabled` + `cfg.HashMaxSize` (1 MB default). `--hash on|off` global flag. `BuildSnapshotWithOptions` computes SHA-256 of file content when enabled and under cap; populates `FileState.Hash`. **Bug fixed during dogfooding (not in original ticket)**
- **Hash-propagation bug in `watcher.DiffSnapshots`.** Before this session, even with hashing enabled the diff was constructing `file.created`/`file.modified`/`file.deleted` events with empty `Hash`. Then `events.Coalesce` (which preserves existing hash when incoming.Hash is empty) would keep the stale baseline hash forever. Fix: propagate `oldFile.Hash` / `newFile.Hash` into the constructed events. Verified by writing same-size content with frozen mtime and watching the hash on the resulting event change.
